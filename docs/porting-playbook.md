# Porting playbook: a Yuke's/THQ Xbox 360 SmackDown game to native PC

Everything learned bringing WWE SmackDown vs. Raw 2008 to a native recompiled build with a native
renderer, written so the next game (SmackDown vs. Raw 2009, same engine family) goes quickly.
Each step lists the tool, what "done" looks like, and the traps that cost time on 2008.

Rules that apply throughout:
- Each game is its own project (folder and repository). Nothing in one game's project reads or
  writes another's; shared code (the launcher) lives in its own repository.
- Game files (ISO, extracted assets, default.xex, generated C++, shader dumps/cache) never go into
  a repository or a release. Players supply their own copy.
- Test runs: a small muted window (`tools\windows\boot_test.ps1`), never on top of someone's
  game session.

## 1. Game files

1. Put your disc image in `iso\` (from an archive: `7z x <archive> -o<root>\iso`).
2. Extract the ISO to `assets\`: `python tools\xiso_extract.py <iso> assets`. `assets\default.xex`
   must exist. (The finished build can also run straight from the ISO, see section 8.)

## 2. Recompile default.xex (ReXGlue SDK 0.10, `sdk\bin\rexglue.exe`)

1. Manifest (`<game>_manifest.toml`): `[project] name`, `game_root = "assets"`,
   `[entrypoint] file_path = "assets/default.xex"`, `out_directory_path = "generated/default"`,
   `includes = ["config/default.toml", "config/pointer_funcs.toml"]`.
2. `config/default.toml` holds per-game midasm hooks: start EMPTY for a new game (every address in
   2008's file is 2008-only).
3. `tools\windows\regen.ps1` -> `generated\default\*.cpp`, log in `logs\codegen.log`.
4. Functions reached only through pointers (vtables, callbacks) are missed by analysis and show up
   as "Unresolved" in the codegen log. 2008 fixed this with a sweep (`tools/sweep.sh`, Ghidra on
   macOS): list pointer targets, add them as `[functions]` in `config/pointer_funcs.toml`, prune
   the ones that split a real function (`config/pointer_exclude.txt`), repeat until clean
   (2008: 75 entries, 0 analysis errors). On Windows: `tools\windows\sweep.ps1` after one launch
   with `SVR_DUMP_IMAGE=logs\default_image.bin` (2009: 56 entries, clean in one pass). Its
   scanner (`tools/native/scan_pointer_targets.py`) takes data words and lis/addi pairs that point
   into code where the previous instruction ends a function (blr, bctr, trap, b, padding) or the
   target has a prologue. Filters that mattered: inline switch tables (two code pointers in a row
   right after a bctr), padding words, and case labels of switch tables analysis already resolved
   (`case N: goto loc_X` in the generated code; ~8000 of them in 2009).
   Hand-found analysis fixes go in `config/default.toml` [functions]; `pointer_funcs.toml` is
   regenerated by the sweep.
   The ~460 "PhysicalHeap::Alloc unable to alloc" errors at boot are the engine probing memory
   size (same count in 2008): harmless.
5. Build: `tools\windows\build.ps1` (clang-cl via CMake presets, `win-amd64-release`).

Done when: the game boots to the title screen on the emulated GPU (SDK xenos/Vulkan backend). Do
that BEFORE the native renderer, so recompilation problems and renderer problems stay separate.

## 3. 60 FPS (game-specific addresses)

SvR keeps a frame-rate mode (2008: struct at 0x82E6E458, +8 target fps). Hooks in 2008
(`src/fps_hooks.cpp`, `config/default.toml`): SetFrameRate(fps) entry (turn 30/25 into 60/50),
the "drop to 30 fps" function (skip), the swap function before VdSwap (FPS counter tick). Find
the 2009 equivalents by pattern: the function writing the target fps, its callers comparing 30/25,
and the function calling VdSwap (`python tools/native/recomp_index.py imports VdSwap`).
Keeping the game in its own 60 fps mode keeps game speed correct (running 30 fps logic at 60
doubled entrance speed in 2008).

## 4. Native renderer: find SvR's D3D functions

The renderer (re:Blue's, adapted; `src/reblue`, glue in `src/native`) hooks SvR's statically linked
XDK D3D library by name; `src/native/svr_d3d_names.h` maps names to addresses.

- `python tools/native/recomp_index.py` builds `logs/recomp_index.pickle`; then `dis <addr>`,
  `callers <addr>`, `imports <name>`, `grep <text>`.
- `tools/native/map_d3d_functions.py` aligns re:Blue's known XDK function sizes to the game's; size
  matches are hints only, verify each by behaviour (what it writes into the device).
- Census build (`-DSVR_D3D_CENSUS=ON`, `tools/native/gen_census.py`) logs which D3D functions the
  game calls and with what; `SVR_DUMP_SHADERS=<dir>` dumps every shader the game creates.
- Functions to map (2008 addresses for reference): Present 8223AEF8, Swap 8223A960, Resolve
  82249340, Clear 8224E9D8, SetRenderTarget 822407E0, SetDepthStencilSurface 82240B48,
  SetScissorRect 8223FD58, BeginVertices 825AAF28, EndVertices 825AB3C8, DrawVertices 825AB3E8,
  DrawIndexedVertices 825AB7D0 (draws live outside the main D3D range), CreateVertexDeclaration
  82242D18, CreateVertexShader 82242FE0, CreatePixelShader 82242ED0, SetTexture 82237868,
  SetVertexShader 822429F8, SetPixelShader 822426F8, SetVertexDeclaration 82242C10,
  SetStreamSource 8223FEA8, SetIndices 82240050, VB Unlock 82235760, IB Unlock 82235868.
  Every name also needs its `__imp__` define, or lld-link silently resolves it to garbage.
- Device layout (stock XDK, verify for 2009's XDK build): size 0x5700; fetch constants +0x480
  (slot*24, 32 slots; vertex fetch constant 95-N = stream N); VS/PS float constants +0x780/+0x1780;
  bool constants +0x2780/+0x2790; register shadows (big-endian dwords) 0x2000@+0x2880,
  0x2080@+0x28C0, 0x2100@+0x28CC, 0x2180@+0x2920, 0x2200@+0x2934, 0x2280@+0x2964,
  0x2300@+0x29B8, 0x2380@+0x2A50; PA_CL_VTE_CNTL +0x294C (0x43F on, 0x400 = viewport disabled);
  PA_SU_VTX_CNTL +0x29C0 (bit 0 clear = D3D9 pixel centres); vertexDeclaration +0x2E24;
  indexBuffer +0x308C; renderTargetShadow +0x3090; depthStencilShadow +0x30A0; stream VBs
  +0x30A4+4N; stream stride/4 bytes +0x30E8+N; viewport floats +0x3160; scissor +0x317C; pixel
  shader +0x318C; vertex shader +0x3190.

## 5. Shaders

Dump (step 4), then the patched XenosRecomp (`third_party/XenosRecomp`, `patches/xenosrecomp-svr.patch`,
built with `-DREBLUE_RECOMP`): `XenosRecomp.exe logs\shaders out.cpp shader_common.h logs\shader_hlsl`,
copy to `generated/native/shader_cache.cpp`. All 449 of 2008's shaders convert. SvR-specific
recompiler changes: 16 vertex input locations (Position0-3, Normal0-3, BlendIndices0,
BlendWeight0, TexCoord0-2, Color0-1, Tangent0), sampler slots 16-31 at shared-constant byte 384,
SVR_SAMPLE (SampleLevel in vertex shaders), DHEN3N normal decode (SPEC_CONSTANT_DHEN3N_NORMAL),
g_ScreenSpace (byte 352) applied before the half-pixel offset.

## 6. Native renderer pitfalls (each cost a session on 2008)

- Null GPU: the SDK's xenos plugin runs a "null" backend; SvR's own D3D library keeps running.
  Hooks must be OBSERVERS (`src/native/svr_hook.h`): call the game's function, then mirror.
  Replacing functions (re:Blue's Blue Dragon style) corrupted the guest heap.
- Never write guest device memory from the renderer (viewport, RT shadows).
- re:Blue's 64 MB guest HostHeap starved the game (Bink frame textures failed -> crash with a
  garbage pitch); renderer objects live in host memory with handles 0x7F000000-0x7FC7FFFF.
- Addresses: texture and VB/IB headers hold CPU addresses in physical aliases; always
  `SvrGpuAddress()` (XDK GPU_CONVERT: +4 KB for the 0xE0000000 alias) then TranslatePhysical.
  Skipping the +4 KB gave green-noise crowd textures; reading as virtual gave device-lost.
- Geometry is bound at draw time from the device (`src/native/svr_geometry.cpp`), checked per
  frame by content hash; D3DIndexBuffer size is exact bytes (odd INDEX16 counts).
- SvR uses fetch slots 16-31: 32 texture slots everywhere, or garbage descriptor indices hang the
  GPU (device lost).
- SvR textures are linear (untiled): 2D and cube mirrors read linear data; 16-bit packed formats
  expand to RGBA8; float formats map directly. Mirrors re-checked per frame by content hash.
- Raw GPUTEXTUREFORMAT bytes collide with re:Blue's D3DFormat enum (6 = kIndex32): tag with
  0xC0000000 before ConvertGuestFormat.
- R32_FLOAT (and R16F, R8G8, R32G32F) must be render-target capable, or depth/shadow resolves are
  skipped silently (blurry depth of field, broken shadows).
- Viewport-disabled draws (post-processing quads) output window pixels: g_ScreenSpace converts
  them; without it a 960x540 black box appears over the frame.
- D3D9 pixel centres: half-pixel offset (+1/w, -1/h) in guest units, or text bleeds atlas rows.
- Present passes the front buffer through unchanged (Blue Dragon's sqrt gamma made SvR white).
- Indexed draws with no/short index buffer are skipped (Vulkan has no "no IB" state).
- Internal resolution: host targets SvrRenderScale() times the guest's size, viewports/scissors
  scaled, screen-space/half-pixel computed in guest units (`svr_render_scale`, 0 = auto).
- `bd::mem::load<be_u32>` byte-swaps twice; use `load<u32>`.

## 7. Debugging tools (all in the native build)

- Crash: `logs/crash_trace.txt` (guest faults and faults in svr2008.exe), hang watchdog
  `logs/hang_trace.txt` (all thread stacks after 10 s without a frame); name frames with
  `python tools/native/symbolize_crash.py <trace>` (uses `out/build/.../<exe>.map`).
- Vulkan errors from plume: `logs/stderr.txt`. VK_ERROR_DEVICE_LOST (0xFFFFFFFC) = GPU fault.
- `SVR_INPUT_SCRIPT="8:START*20@2,50:A*90@2,51:LEFT*90@2"` reaches a match in ~2 min.
- `SVR_DRAW_LOG=<frame>`: every draw/clear/resolve of one frame (targets, viewport, shaders,
  textures, vertex bytes, depth state, DOF constants).
- `SVR_SKIP_DRAWS=<bitmask>` (1 indexed, 2 DrawVertices, 4 BeginVertices, 8 non-RGBA8 targets,
  16/32 lit/unlit indexed, 64/128 skinned/static): bisect GPU faults and wrong output.
- `SVR_PRESENT_TARGET=<guest texture va>`: show an intermediate (e.g. the depth copy).
- `SVR_MIRROR_NO_MIPS=1`: base level only.

## 8. Packaging and release

- Portable layout: game found next to the exe (`assets\` or any `.iso`, read in place), else a
  file picker (remembered in `<game>-game.txt`); saves in `userdata\`; settings in `<exe>.toml`
  (`fullscreen`, `svr_60fps`, `log_file`, `svr_render_scale`).
- `tools\windows\package_portable.ps1` builds `dist\` (add `-NoAssets -NoSave` for a public zip).
  The same Windows zip runs on Steam Deck through Proton (tested 2008: flawless).
- Release model: prebuilt download (launcher + game), players supply their own disc image. 2008
  and 2009 are released together.

## 9. What SvR 2009 added (ported in one day with this playbook)

- **Emulated stage:** use `--gpu_backend=vulkan`; the SDK's D3D12 backend hung (DEVICE_HUNG) when
  2009 loaded a match. `src/input_script.cpp` (now in every build) reaches a match unattended.
- **Finding a game's functions from 2008's:** `tools/native/match_functions.py OLD_IMAGE NEW_IMAGE
  ADDR...` aligns functions by shape (immediates masked, bounds from `.pdata` plus leaf functions)
  and maps hook sites inside them; `tools/native/device_offsets.py OLD NEW old=new...` turns
  matched D3D functions into a device-layout translation. Confirm every match by the fields it
  writes and by its callees (Present calls Scissor, SetRenderTarget, Sync, Swap, Resolve).
- **2009's device:** 0x5E00 bytes; same as 2008 up to +0x2AC0, then 8 bytes later from the vertex
  declaration (+0x2E2C) on; the present interval moved to +0x351C. 2009 links no non-indexed
  DrawVertices (`SVR_NO_DRAW_VERTICES`). Verified map: `config/native/d3d_names.toml`.
- **Shaders:** 2009 passes COLOR3/COLOR4 between stages; XenosRecomp declares COLOR0-4 under
  `REBLUE_RECOMP` (21 interpolators). `tools/native/build_shader_cache.ps1` builds XenosRecomp
  and the cache. Shaders can't be found statically in the game files (EPAC archives are packed),
  so they come from a shader-dump run.
- **Fetch-constant swizzle:** textures can carry a component swizzle (BGRA `0x60A`, luminance
  `0xA00`); the mirror's view applies it (`ApplyFetchSwizzle`). Without it 2009's title logo had red
  and blue swapped, and 2008's title logo was washed out.
- **Screen shape:** SvR always draws 16:9; Auto aspect keeps 16:9 with bars on 16:10 screens
  (Steam Deck), `bd_aspect_ratio = 6` stretches.
- **Internal resolution auto** follows the display (not the window) and stays 1x on the Deck
  (`SteamDeck=1`).
- **Build safety:** `build.ps1` always passes `SVR_NATIVE_RENDERER`; a CMake cache reset (cached
  compiler path changed) once silently rebuilt 2008 with the emulated GPU and MSVC.
- **Releases:** the shared launcher (`launcher/`, its own repository) plus one game per release;
  `tools/windows/package_release.ps1`. Third-party sources are pinned commits plus `patches/`,
  checked to reproduce the working copies exactly.
